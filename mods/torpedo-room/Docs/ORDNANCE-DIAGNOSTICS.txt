INSTALL: replace the old Source folder completely and restart. No uninstall cleanup needed merely to update. Use a separate save. All MP peers should use the same test build.

CHANGE: At a tube station, the tube-door inventory entry now supplies the same camera-selected operator as our Manage Ordnance button, instead of native's null-character/global-queue path. This binding only applies inside that native tube action call, for its exact ship/group/storage. Normal FPP walk-up interactions and intentional global crew orders stay native. Native role eligibility and rejection are preserved; a leader is never substituted with an engineer and no automatic global fallback is added. Load-and-maintain does not grant permission for separate maintenance of a loaded torpedo.

The .31 handoff remains: retain the exact actor/activator/action and wait for continuous calm camera/interaction state for 0.5 seconds, resetting on camera changes, up to 8 seconds. Player task/actor/view changes, disabling the interface or world changes abort. Brief native save protection is released on completion of the handoff/abort/reset.

TEST at 1x, one attempt at a time from the same starting save:
1. Quick-swap an ENGINEER from TDC/scope to the tube station. Open the tube's own ordnance interaction. Request maintenance on an eligible loaded torpedo. It should start without leaving/deselecting the engineer manually.
2. Repeat through our Manage Ordnance button as the comparison.
3. Quick-swap a LEADER and request separate maintenance through each entry. Preserve the native warning/rejection. Do not expect another engineer to pick it up automatically. Observe whether any global task appears; this is a regression check, not a claimed live pass.
4. Through the tube entry, test Load only and Load and maintain with an eligible operator. Preserve the native choice/prompt.
5. Close inventory with Escape without ordering work: initial room screen should return. Ordinary unrelated/global inventory behavior should remain native.
If a request fails, wait 15 seconds without walking over, reissuing or rescuing the task. Send the session output_log and attempt order/actors. No additional diagnostic mod or setting is required.

DIAGNOSTICS: look for startup 'Native tube inventory operator binding installed', ORD-DIAG BIND and DEFER lines, and native task starts/stops. The first ENTER StorageUI.Open diagnostic may still show character=null because it runs before the new binding prefix; RETURN and inventoryActor show the actual bound character. Each inventory opening starts a 90-second/300-line window; up to six camera caller stacks per session. Async StartAction RETURN is not task completion. Logs include crew names/positions and potentially stack paths; no automatic uploads.

No live .32 run here. Offline doubles do not prove native crew eligibility, Unity/Harmony/MP event timing, animation completion or save safety in-game. Prior exit crash/physical aft door mismatch remain unconfirmed. No torpedo physics, dud checks, depth policy, config migration or TRC9 changes.

Last station still uses shared vanilla FAT/LUT values at launch, not a previously configured/fired torpedo. Optional Hidden Reports reference-tube preset and per-tube viewport dials remain queued only.
